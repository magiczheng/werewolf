# 🐺 狼人杀 · 聚会助手（Werewolf Party）

网页版狼人杀辅助平台，专为**线下聚会**设计。手机扫码/输入房间号即可加入，App 负责**发牌、阶段流转、投票与结算**；玩家照常线下发言，但身份保密、夜间操作与白天投票都在各自手机上完成。

- **法官模式**：玩家在 App 内提交夜间操作，法官面板实时汇总，法官确认后手动推进阶段。
- **无法官模式**：房主点开始后自动发牌，之后由各阶段的操作人点「结束」推进，投票也在界面上完成。

## 功能特性

- 📱 **可安装到主屏幕**（PWA），独立窗口全屏运行，适配刘海与底部手势条
- 🎨 玻璃拟态深色主题：极光背景、半透明层叠卡片
- 🧭 游戏页底部 Tab 导航（操作 / 板子 / 播报 / 法官），当前阶段的操作永远在首屏、单手可及
- 🎲 8~16 人局，按人数自动配置经典角色板子，可微调（创建房间时**默认 9 人**：3 狼 + 3 神 + 3 民）
- 🃏 每位玩家只看到自己的角色牌，狼人可见狼队友
- 🙈 **防偷看**：身份牌开局后自动收起，需按住顶栏的「👁 身份」才显示，松手即消失；显示时用中性深色配色，不用狼红/好人绿的色块——旁边的人扫一眼只看到一块暗屏，而不是一眼可辨的阵营信号
- 🔮 预言家**每晚只能查验一人**，同一人不能重复查验；查验结果直接显示在操作卡片上（不用一闪而过的提示），历次结果的身份牌保持翻开
- 🌙 夜间操作：守卫 → 狼人 → 女巫 → 预言家。**狼人刀人采用队内投票，少数服从多数**（无人过半则清空重投）；全员选完且有结果即自动进入下一阶段
- 🔊 **语音播报**：解说员设备（房主 / 法官）用系统语音念出每条播报，像真人念旁白；可在「播报」页一键静音
- 📢 **全程阶段播报**：**天黑请闭眼**（进入夜晚时必报，与是否有守卫无关）、狼人请睁眼、请选择击杀对象…每个阶段进入时都会向全场播报一句（措辞不提座位号，避免泄露身份）
- 🚨 警长竞选：上警/退水、警上发言、警下投票、平票 PK、警长 1.5 票
- 💣 **狼人白天自爆**：翻牌亮身份立即出局、没有遗言，当天白天立刻结束进入黑夜；若正在投票则投票作废（详见下方规则）
- 👑 猎人殉枪、白痴翻牌免死、白狼王自爆带走一人、女巫一救一毒（仅首夜可自救）
- ⏱️ **没有阶段倒计时**：何时推进完全由桌上的人决定，不会因为读得慢被计时器推着走
- 📱 微信/浏览器扫码加入（二维码由服务端按访问 Host 生成，局域网/公网通用）
- 🔑 邮箱 + 密码注册登录，**需登录才能创建/加入房间**；同一账号跨设备身份一致
- 💾 断线/刷新自动重连，保留座位与身份
- 👨⚖️ 法官模式：法官可见全部身份与操作汇总，可手动改生死、强制结算
- 💺 **换座方便**：入座后可直接点别的空位换过去，也能「离开座位」把位置让出来
- 🔁 **结算后不用退出**：房主可「回到房间」直接开下一局（座位会清空，大家重新选座）；想走的人可以「退出房间」回到主界面

## 技术栈

- Node.js + Express + Socket.IO（单服务器、内存态对局 + SQLite 存账号）
- 纯原生前端（ES Modules），**零构建步骤**，Socket.IO 客户端由服务端内置提供（不依赖 CDN，可离线）
- 玻璃拟态深色主题；**不加载任何 Web 字体**——中文字体动辄数 MB，与「离线可用」冲突，改用精调系统字体栈
- PWA：可添加到主屏幕、独立窗口显示、刘海与手势条安全区适配
- `node:test` 驱动的引擎单测 + Socket.IO 集成测试 + 前端渲染回归

## 本地运行

要求 Node.js ≥ 18。

```bash
npm install
npm start          # 启动，默认 http://localhost:3000
# 开发热重载：npm run dev
# 跑测试：      npm test
```

`npm install` 会安装 `better-sqlite3`（有主流平台的预编译二进制；无预编译时会自动编译，需要本机有 C 编译工具链）。

同一局域网内，其他人用手机浏览器打开 `http://<你的内网IP>:3000` 即可（分享链接由服务端按请求 Host 自动生成，扫码即达）。

## 账号与数据

- **注册 / 登录**：打开首页即见登录卡片，可切到「注册」。注册只需邮箱 + 密码（昵称可选，不填用邮箱前缀）。**登录后才能创建或加入房间**；同一账号在不同设备/浏览器上身份一致（断线重连、换设备都能回到原座位与身份）。
- **存储**：账号与会话保存在 SQLite，默认 `data/werewolf.db`（可用环境变量 `DB_PATH` 指向别处）。密码用 Node 内置 `crypto.scrypt` 加盐哈希存储，不存明文。
- **会话**：登录后浏览器本地保存一个会话令牌（localStorage `ww_token`），每次连接握手自动携带恢复登录；退出登录后令牌立即在服务端失效。令牌暴露在浏览器本地存储中——本应用为原生 JS、无第三方脚本且所有用户内容都已转义，风险可控；若后续完全公网部署且引入不可信内容，建议改为 HttpOnly Cookie。
- **防护**：注册/登录按 IP 限频（默认每 IP 每分钟 20 次），密码至少 6 位，邮箱做基本格式校验。

## 玩法说明

1. **注册/登录**：打开首页先注册账号并登录（同一账号跨设备身份一致）。
2. **创建房间**：登录后填昵称 → 选人数 → 选「法官模式 / 自动模式」→ 微调角色板子与规则开关 → 创建。**配置在这一步定好，进入房间后不能再改**，只能查看。
3. **加入房间**：扫房主分享的二维码，或输入 6 位房间码；需要先填昵称。
4. **选座位**：所有人都必须选择座位号入座；满员后房主/法官点「开始游戏」。
   - **换座**：已入座的人**直接点别的空位**即可换过去，引擎会自动让出旧座位，不用先起立。
   - **离开座位**：点「离开座位」把位置让出来，之后可以重新选座，或把位置让给别人；离开的人会回到「等待选座」列表。
   - 开局后座位锁定，不能再换座或起立——否则座位与身份会对不上。
5. **确认身份**：开局后每位玩家看到自己的角色牌，**记住后点「我已记住身份」**。所有人都确认后才进入夜晚（这一步是全员操作型，不设倒计时）。
6. **查看身份**：进入夜晚后身份牌自动收起。需要再看时，**按住顶栏的「👁 身份」**即可显示，松手立刻消失（切到后台或按 Esc 也会收起）。这样手机放在桌上不会一直亮着身份。
7. **推进阶段**：没有倒计时。夜间由对应角色点「结束本阶段」；警长发言与遗言由发言者点「结束发言」；天亮播报与白天发言由房主点「进入下一步」；确认身份/上警/投票在所有人操作完后自动推进。**没有「跳过阶段」按钮**，详见下方「阶段推进」。
8. **法官模式**：夜晚各自在 App 内提交操作（守卫守谁、狼人杀谁…），法官面板实时显示汇总，**由法官点「下一步」推进所有阶段**；白天投票照常。
9. **结束**：结算页公布全部身份与胜负。房主点「回到房间，再来一局」即可开下一局——**座位会清空**，大家重新选座再开始；任何人也可以点「退出房间」回到主界面。

## 规则配置

**角色板子（默认 8~16 人）**

| 人数 | 狼人 | 白狼王 | 预言家 | 女巫 | 猎人 | 守卫 | 白痴 | 村民 |
|----|----|----|----|----|----|----|----|----|
| 8 | 3 | - | 1 | 1 | 1 | - | - | 2 |
| **9** | 3 | - | 1 | 1 | 1 | - | - | 3 |
| 10 | 3 | - | 1 | 1 | 1 | 1 | - | 3 |
| 11 | 4 | - | 1 | 1 | 1 | 1 | - | 3 |
| 12 | 4 | - | 1 | 1 | 1 | 1 | 1 | 3 |
| 13 | 4 | - | 1 | 1 | 1 | 1 | 1 | 4 |
| 14 | 4 | - | 1 | 1 | 1 | 1 | 1 | 5 |
| 15 | 5 | - | 1 | 1 | 1 | 1 | 1 | 5 |
| 16 | 5 | - | 1 | 1 | 1 | 1 | 1 | 6 |

> 加粗的 9 人局是**默认配置**（主流玩法：3 狼 + 3 神「预言家/女巫/猎人」+ 3 民，**不含守卫**）。
> 白狼王默认关闭；房主可在创建时开启并替换同等数量的普通狼人。

**规则开关（创建房间时可选）**

- 女巫首夜可自救（默认开）
- 守卫 + 女巫同盾：守救同盾平安夜（默认）；若选「守救相克」，被守护又被救的人会死亡
- 警长 1.5 票（默认开）
- 屠边规则（**默认开**）：狼人杀光所有**神职**或所有**平民**即获胜；关闭则退回屠城（狼人数量追平/反超好人即获胜）
- 女巫仅首夜可自救（默认开）：过了第一夜被刀不能自救，但救别人不受此限
- 被放逐的玩家公开翻牌（**默认关闭**：放逐只公布「谁出局」，不公布身份）

**阶段推进：没有任何倒计时**

何时进入下一阶段，完全由人决定：

| 阶段 | 谁点「结束」 |
|----|----|
| 确认身份 / 上警 / 各类投票 | 相关玩家**全部操作完自动推进**（无需任何人再点） |
| 守卫 / 女巫 / 预言家行动 | 对应角色本人（操作完点「结束本阶段」） |
| 预言家查验 | 每晚限一人、不可重复；结果直接写在操作卡片上，历次记录的身份牌保持翻开 |
| 狼人行动 | **队内投票**：全员选完且有人过半即**自动进入下一阶段**，无需任何人点结束 |
| 警长竞选发言 | 当前发言者点「结束发言」 |
| 警长竞选 · 无警下玩家 | **自动判警徽流失**，直接进入白天（公告见下） |
| 遗言 | 仅**被投票放逐**时才有；由该玩家点「结束发言」 |
| 天亮播报 / 白天自由发言 | 房主点「进入下一步」 |
| 猎人开枪 | 猎人选择开枪或放弃（**不公布是谁在开枪**，猎人的身份是暗的） |
| 猎人开枪 / 警徽移交 | 动作本身就是结束（放弃亦有对应按钮） |

这样线下聚会时节奏完全由桌上的人掌握。

**狼人夜间采用队内投票**（与其它阶段规则不同）：

- 每只狼各投一票，**全员选完之前阶段不会推进**——一只狼不能替全队收工
- **少数服从多数**：得票**严格过半**才算数。3 狼要 2 票、4 狼要 3 票、2 狼必须一致
- **全员选完且有人过半 → 自动进入下一阶段**，狼人不需要（也没有）「结束本阶段」按钮
- **无人过半则清空所有票，重新投票**（例如 3 狼各投各的）
- 票型只在狼队内部共享，好人与法官面板都看不到
- 重投只发生在狼队内部，不会出现在公共播报里

### 警长竞选：警下无人时的处理

上警的玩家只能竞选/发言、**没有投票权**；只有**没上警（警下）的玩家**能投警长票。
因此当**所有存活玩家都上警**时，警下为 0 人，没人有资格投票——
此时直接判定**警徽流失、本局无警长**，跳过全部竞选发言，直接进入当天白天流程。

播报会明确写出：

> 全体上警，无警下玩家，警徽流失，本局无警长

同理，**无人上警**时也直接判警徽流失。

**遗言只在被投票放逐时才有**：夜里被刀 / 被毒 / 守救相克、猎人开枪带走、白狼王自爆带走——都不留遗言。
（被刀的猎人仍然可以开枪，只是没有遗言。）

**夜间角色的出局不会让它的阶段消失**：守卫 / 女巫 / 预言家出局后（女巫是两瓶药都用完），它的阶段**照常出现**，
只是无人可操作，停留一个**随机 3~10 秒**后自动走过。

> 为什么必须这样：阶段一旦被跳过，「守卫阶段没出现」就等于当众宣布守卫已死；
> 「女巫阶段没出现」更糟——等于告诉狼人女巫没药了、可以放心刀。
> 停留随机时长后，从外面无法区分「这个角色出局了」和「这个角色行动得快」。
> 延迟对客户端不可见（不下发 masked / maskUntil），否则倒计时本身又成了信号。
> 板子里压根没有的角色仍然直接跳过——那是公开配置，再演一遍只是浪费时间。

**没有「跳过本阶段」**：每个阶段只由它自己的操作人推进（房主负责天亮播报与白天发言）。
房主出局后**仍然**能推进这两个阶段。

> ⚠️ 这意味着**没有任何手动兜底**：若某个操作人掉线且不回来，该阶段会一直停在那里，只能重开一局。

**法官模式**：节奏一律由法官点「下一步」推进，玩家侧不出现「结束」按钮——这正是法官模式与自动模式的区别。

### 语音播报

播报会用**浏览器内置的语音合成**念出来（`speechSynthesis`），不联网、不依赖任何服务，走操作系统自带的语音引擎。

**只有一台设备会说话**：房主（法官模式下即法官）那一台。一屋子 9 部手机同时念旁白是灾难，线下游戏本来就是一个人念旁白。
语音开关也只在这台设备上出现（其他设备根本不朗读，给个开关只会误导）。

**不会重复念**：每条播报在服务端带一个单调递增的 `id`，客户端靠它判断「这条念过没有」。不能用数组下标——播报上限 40 条，满了会从头部裁掉，下标会整体错位。
换房间时游标会重置；静音期间照常推进游标，重新开启后不会把攒下的旧播报一股脑补念出来。

> 若系统没有中文语音包，会退回默认音色按 `lang=zh-CN` 朗读，效果取决于系统。

### 狼人自爆

**时机**：只能在**白天**的发言 / 讨论 / 投票 / 警长竞选阶段自爆，**夜晚不能**。

**效果**：
- 自爆的狼**翻牌亮明身份**，立即出局，**没有遗言**
- 当天白天**立刻结束**，直接进入黑夜

**投票影响**：若正在进行投票（放逐或警长竞选），**投票作废**，不公布放逐结果。

**后续行动**：自爆者已出局，**不能参与当晚刀人**，其余狼人正常行动；
若他是最后一只狼，**好人直接获胜**。

> **白狼王**自爆是它的角色能力：除了上述效果，还会**带走一名玩家**（需要选目标）。
> 普通狼人自爆则不带人。

## 公网部署

把服务跑在云服务器上即可全球可玩（无公网访问时，同一局域网也能用）。

### 直接运行

```bash
# 装依赖并启动（默认 3000 端口）
PORT=3000 npm start
```

可用 `PUBLIC_URL` 固定分享链接前缀（一般不需要，分享链接会自动按访问域名生成）：

```bash
PUBLIC_URL=https://werewolf.example.com PORT=3000 npm start
```

### 用 Docker（推荐）

```bash
docker compose up -d --build     # 构建并启动
docker compose logs -f           # 看日志
docker compose down              # 停止（数据保留）
```

启动后访问 `http://<主机>:3000`。

**数据位置**：SQLite（账号、会话）保存在 **`docker-compose.yml` 旁边的 `data/` 目录**里，
通过 `./data:/app/data` 挂载进容器。删容器、重建镜像、`docker compose down` 都不会丢账号。

> **Linux 上的一个坑**：容器以内置的 `node` 用户（uid 1000）运行，宿主机上的 `data/` 必须对它可写，
> 否则启动即失败。先执行：
> ```bash
> mkdir -p data && sudo chown -R 1000:1000 data
> ```
> macOS/Windows 的 Docker Desktop 会自动处理属主映射，不需要这一步。

**镜像来源**：默认本地构建（`build: .`）。也可以用 CI 推到 GHCR 的镜像——把 compose 里的
`build` 注释掉、启用 `image: ghcr.io/magiczheng/werewolf:latest` 即可。

### 用 systemd 守护进程（可选）

```ini
# /etc/systemd/system/werewolf.service
[Unit]
Description=Werewolf Party
After=network.target

[Service]
WorkingDirectory=/opt/werewolf
ExecStart=/usr/bin/node server/index.js
Restart=always
Environment=PORT=3000

[Install]
WantedBy=multi-user.target
```

### nginx 反向代理（HTTPS + WebSocket）

应用同时使用 HTTP 与 WebSocket（Socket.IO），反向代理必须显式转发 `Upgrade` 头：

```nginx
server {
    listen 80;
    server_name werewolf.example.com;

    # 建议加 HTTPS（certbot 一键签发证书）
    # listen 443 ssl;
    # ssl_certificate     /etc/letsencrypt/live/werewolf.example.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/werewolf.example.com/privkey.pem;

    # 需要足够大的 body 与较长的 proxy 超时（WebSocket 长连接）
    client_max_body_size 5m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Socket.IO / WebSocket 升级
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

> 若应用跑在 HTTPS 反向代理之后，二维码生成的 `http://` 前缀会被浏览器拦截为「不安全内容」——此时请设 `PUBLIC_URL=https://werewolf.example.com` 覆盖分享链接前缀。

> **账号安全建议**：公网部署务必启用 HTTPS（否则密码与登录会话在网络上明文传输）。用户密码始终以 scrypt 加盐哈希存储，不受传输层影响；但会话令牌（浏览器 localStorage）的暴露面与是否走 HTTPS 相关。

## 多账号测试模式

想在**一个浏览器**里同时登录多个账号（例如自己开一桌调试、或一人分饰房主与玩家）时用：

```bash
npm run dev:multi      # 等价于 MULTI_ACCOUNT=1 node --watch server/index.js
```

开启后，**每个标签页拥有独立的登录会话**，可以各登录一个账号、各进各的房间，刷新也不会串号。页面顶部会出现一个橙色角标提示当前处于该模式。

**为什么默认做不到**：登录会话存在 `localStorage`，而 localStorage 在同源的所有标签页之间是共享的。两个标签页登录不同账号会互相覆盖，任何一次刷新都会静默变成对方的账号。测试模式改用 `sessionStorage`（每个标签页独立）来解决，并且**不做跨标签页继承**——新开的标签页一律是未登录状态，需要自己选账号。

**测试模式下还会跳过「确认身份」阶段**：开局直接发牌进夜晚，不用在 8~9 个标签页上各点一次「我已记住身份」。
角色照常发放，只是省掉确认这一步；页面顶部角标会写明「已跳过确认身份」。

**这两个开关默认都关闭**：不设 `MULTI_ACCOUNT` 时，服务端注入 `window.__WW_MULTI__=false` 与 `window.__WW_SKIP_REVEAL__=false`，
会话仍走 localStorage、开局仍停在确认身份阶段，行为与之前完全一致。因此它们只影响你显式开启的运行，不会波及正式使用。

| 环境变量 | 作用 |
|----|----|
| `MULTI_ACCOUNT=1` | 会话按标签页隔离 + 播种测试账号 + **跳过确认身份** |
| `SKIP_ROLE_REVEAL=0` | 即使开了测试模式，也保留确认身份阶段（想在测试环境验证这个流程时用） |
| `SKIP_ROLE_REVEAL=1` | 单独强制跳过确认身份（不开多账号模式也行） |

不想开服务端开关也可以：**无痕窗口**天然有独立的存储分区，同样能和一个正常窗口并存两个账号。

> 同一条 Socket 连接上仍然只能是一个账号——那是服务端的账号模型，多账号靠的是每个标签页各建一条连接。

## 测试账号

开启测试模式后（`MULTI_ACCOUNT=1`，或显式 `SEED_ACCOUNTS=1`），服务启动时会确保存在这 9 个账号（数量见 `server/config.js` 的 `TEST_ACCOUNT_COUNT`）：

| 邮箱 | 密码 |
|---|---|
| `1@qq.com` … `9@qq.com`（9 个） | `111111` |

登录页底部会出现「测试账号一键登录」，点数字即可直接登入，省去开 8 个标签页时手打 8 次邮箱密码。按钮行用金色虚线框标出，不会和正式功能混淆。

**「确保存在」的含义**：不只是「不存在才创建」。如果这些邮箱已被别的密码占用，种子会**把密码重置为 `111111` 并显式记录**——否则「密码都是 111111」这个前提会静默不成立，而一个会悄悄说谎的测试开关比没有更糟。不想动既有账号就设 `SEED_RESET_PASSWORD=0`，此时只报告不修改（但一键登录对密码不符的账号不可用）。

> ⚠️ **两个注意事项**
> 1. 这些账号写进的是**正式的 `users` 表**并会持久化，不是单独的测试库。若之后用同一个 `DB_PATH` 跑公网部署，请先删掉它们或换库——`111111` 这种密码不该出现在公网。
> 2. 重置密码会**注销该账号的全部既有会话**。如果你之前用 `1@qq.com` 建过房间，重置后那些标签页需要重新登录。

## 关于 App（PWA）

应用可「添加到主屏幕」，以独立窗口全屏运行，并适配刘海与底部手势条。

**但有一点必须说清楚**：Service Worker 只在**安全上下文**（HTTPS 或 localhost）下才能注册。本项目最常见的用法是手机扫码访问 `http://192.168.x.x:3000`——这是不安全源，SW 无法注册。因此：

| 场景 | 添加到主屏幕 | 独立窗口 | 离线 |
|----|----|----|----|
| iOS Safari · 局域网 HTTP | ✅ 可用 | ✅ 可用 | ❌ |
| Android Chrome · 局域网 HTTP | 仅创建书签快捷方式（无安装提示） | ❌ | ❌ |
| 任意平台 · HTTPS / localhost | ✅ 可用 | ✅ 可用 | 仅外壳 |

- 客户端已用 `isSecureContext` 守卫，HTTP 下跳过注册，**不会报错，也不影响任何功能**。
- **不要期待离线可玩**：所有对局状态都走 Socket.IO 实时推送，断网只能看到外壳和一句「连接已断开」。SW 的实际收益是让 Chromium 愿意弹安装提示、以及 PWA 冷启动快一点。
- **扫码入局走的始终是浏览器**，不会是已安装的 PWA——这是 PWA 的固有行为。PWA 的收益主要在房主/法官这类会反复打开应用的角色。
